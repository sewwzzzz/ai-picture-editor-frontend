# 路由渲染

## 路由更新源码去细节版

```tsx
// ───────── ① router：闭包自己持有 state 和订阅数组 ─────────
const createRouter = (routes) => {
  let state = { location: '/', matches: [] }      // router 的 state（纯 JS 变量）
  const subscribers = new Set()

  return {
    get state() { return state },
    subscribe: (fn) => {                           // ← setState 会被 add 进来
      subscribers.add(fn)
      return () => subscribers.delete(fn)
    },
    // URL 事件（popstate / navigate）进来
    onUrlChange: () => {
      state = computeNextState(routes)             // ② 重算 state（router 自己改自己）
      subscribers.forEach((fn) => fn(state))       // ③ 调用所有 subscriber 回调
    },
  }
}


// ───────── ④ RouterProvider：setState 注册进 router 的 subscribers ─────────
const RouterProvider = ({ router }) => {
  const [state, setState] = useState(router.state)

  useLayoutEffect(() => router.subscribe(setState), [router])
  //                                  ↑ setState 被放进 router 的 subscribers 里

  // ⑤ 回调触发 setState → RouterProvider 重渲染 → 重新执行 return
  return (
    <DataRouterContext.Provider value={{ router, navigator }}>
      {/* ⑥ 把新 state 作为 value 传给 Provider */}
      <DataRouterStateContext.Provider value={state}>
        {/* ⑦ React 渲染 Provider 时，把 value 写进 Context._currentValue */}
        <Routes />
      </DataRouterStateContext.Provider>
    </DataRouterContext.Provider>
  )
}

// ───────── ⑧ 消费者：读 Context 的 _currentValue ─────────
const useLocation = () => useContext(DataRouterStateContext).location


```

## 本质

`router.state` 是纯 JS 变量，React 感知不到它的变化。

因此借助订阅机制：router 发生变化时回调 React 的 `setState`，把新的 `router.state`（一份副本）写进 React 状态——这样 React 才能"察觉"这次发生在外部的变化，进而重新渲染。

即：

```
router.state 变化（纯 JS，React 看不见）
  → 订阅回调被触发
  → setState(newState)（写入 React 状态）
  → React 重渲染，Provider 拿到新 value，消费者更新
```
