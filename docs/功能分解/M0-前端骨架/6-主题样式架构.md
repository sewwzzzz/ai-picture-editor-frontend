# 主题样式架构

> 对应 PRD：适配不同主题的样式结构，确保正常切换。基础为白天 / 黑夜两套，架构需可扩展第三套及以上。
> 参考视觉：白天的创作页 / 编辑器 / 导出 / 批量四张截图——**中性浅灰底 + 白卡片 + 近黑主按钮 + 浅描边**的定制风格（shadcn 一派）。

## 决策视角（选型）

> **先划清两件事**：**选哪个主题（状态）** 与 **颜色怎么变（呈现）** 是两层。状态已在 4 号文档定为 Zustand 全局字段（`theme`）；本文件解决「呈现」——组件如何消费颜色，才能让换主题**不碰组件代码**。

| 方案 | 运行时开销 | 扩展新主题的方式 | 与截图风格匹配 | 依赖 | 本项目 |
| --- | --- | --- | --- | --- | --- |
| **A. CSS 变量 + `data-theme`** | 零 | 加一段变量覆盖 | 高（token 体系正是此类风格的实现方式） | 0 | ✅ **推荐** |
| **B. Tailwind CSS v4** | 零（构建期） | `dark:` variant + `@theme` | 高（shadcn 同源） | +构建链与类名约定 | 中：一揽子引入，M0 不必 |
| **C. CSS-in-JS**（styled-components 等） | 有（运行时插样式） | 换 ThemeProvider | 中 | +运行时依赖 | 低：画布高频场景应避免 |
| **D. 组件库主题**（AntD / MUI） | 零 | ConfigProvider token | 低（自带视觉体系，难贴定制风） | +大包体 | 低：编辑器多为自绘组件 |

## 方案（单选）

- [x] CSS 变量（原生 custom properties）+ `data-theme` 切换
- [ ] Tailwind CSS v4
- [ ] CSS-in-JS
- [ ] 组件库主题系统

> **单选理由**：
> 1. **命中「可拓展」的本质**：组件只消费**语义 token**（`var(--color-surface)`），主题 = 一组变量值。新增主题只需在 `tokens.css` 加一段覆盖，**组件零改动**——这正是任务要求的「可拓展」。
> 2. **零依赖、零运行时**：浏览器原生能力，Vite 直接支持，不增加包体与首帧开销。
> 3. **与截图风格同构**：参考视觉是「语义 token 驱动」的中性色体系（近黑主按钮 / 白卡片 / 浅描边），用 CSS 变量实现是同一条路，token 命名可直接对齐。
> 4. **与 4 号文档一致**：`theme` 状态已在 Zustand store；CSS 变量只管「怎么呈现」，store 只管「选了哪个」，职责分离互不侵入。
> 5. **为 Tailwind 留后路**：Tailwind v4 原生基于 CSS 变量（`@theme`）。先立 token 体系，后续若引入 Tailwind，现有变量直接映射，无需返工。
>
> **不选 Tailwind（现阶段）**：M0 没有既定样式框架，引入 Tailwind 是一揽子决策（类名风格、团队约定、与现有 CSS 的边界）；主题架构并不依赖它。UI 组件量上来（M2+ 表单变多）后再评估。
>
> **不选 CSS-in-JS**：运行时插样式拖慢首帧，React 19 生态在收缩，且与「画布高频更新」的项目气质冲突。
>
> **不选组件库主题**：截图是定制中性风，AntD / MUI 自带的视觉体系难贴合；编辑器主体是自绘组件（Konva + 自定义面板），组件库收益低、包体大。

## 设计

### 三层结构

```
① 语义 token（app/styles/tokens.css）   ← 唯一真源：--color-bg / --color-surface / ...
        │  组件只允许消费这一层
        ▼
② 组件样式                              ← 只写 var(--token)，禁止硬编码色值
        │  切主题时
        ▼
③ html[data-theme] 切换                 ← 改一个属性，CSS 级联全站重绘
```

> 原始色板层（primitive，如 `--gray-500`）M0 不建；等出现「同一主题内也要换色板」的需求再加，避免过早抽象。

### 语义 token（初值，从截图提取，落地时校准）

| token | 用途 | Light（截图） | Dark（对偶） |
| --- | --- | --- | --- |
| `--color-bg` | 页面 / 画布区背景 | `#F6F6F4` | `#0F0F10` |
| `--color-surface` | 卡片 / 面板 / 侧栏 | `#FFFFFF` | `#1A1A1D` |
| `--color-fg` | 主文本 | `#1C1C1A` | `#F4F4F5` |
| `--color-fg-muted` | 次要文本 / 占位符 | `#71717A` | `#9D9DA6` |
| `--color-border` | 边框 / 分隔线 | `#E4E4E7` | `#2A2A2E` |
| `--color-primary` | 主按钮底（生成 / 打包） | `#18181B` | `#F4F4F5` |
| `--color-primary-fg` | 主按钮文字 | `#FFFFFF` | `#18181B` |
| `--color-accent` | 选中 / 悬停底（导航激活项） | `#EDF1F5` | `#232329` |
| `--color-accent-fg` | 选中态文字 | `#1C1C1A` | `#F4F4F5` |
| `--radius-card` / `--radius-control` | 卡片 12px / 控件 8px | — | 同 light |
| `--shadow-card` | 卡片阴影（极浅，靠描边区分） | `0 1px 2px rgb(0 0 0 / 4%)` | `0 1px 2px rgb(0 0 0 / 40%)` |

> token 命名一律**语义**（`primary` / `surface`），不取色名（`black` / `gray-900`）——否则换主题时组件里的名字就撒谎了。

### 切换机制

```
Zustand store（theme: 'light' | 'dark'，初始值读 localStorage → 回落系统偏好）
        │ setTheme / toggleTheme
        ▼
useThemeSync（app/ 装配层的订阅）
        │ 写 documentElement.dataset.theme
        │ 写 localStorage['app-theme']（启动镜像）
        │ 写 color-scheme（让原生控件跟随）
        ▼
CSS 级联：[data-theme='dark'] 覆盖变量 → 全站重绘
```

- **组件不重渲染**：换主题只改 `html` 上的一个属性，颜色变化由 CSS 级联完成；Zustand 里的 `theme` 状态只服务「切换按钮的选中态」和持久化。这是本架构和「把颜色存 React state」方案的本质差别。
- **防闪烁（FOUC）**：`index.html` 内联一段脚本，在**首帧绘制前**读 `localStorage['app-theme']`（缺省再查 `prefers-color-scheme`）设置 `data-theme`。用独立的裸 key 而非 Zustand persist 的存储，避免内联脚本依赖 store 内部格式。
- **`color-scheme` 同步**：`light` / `dark` 与 `data-theme` 一起设，滚动条、原生输入控件自动跟随。

### 可扩展：加第三套主题怎么做

1. `tokens.css` 加一段 `[data-theme='sepia'] { --color-bg: ...; ... }`；
2. `theme` 的类型联合加一项（`'light' | 'dark' | 'sepia'`）；
3. 切换入口出现第三项。

**组件与页面零改动**——这是验收「架构可拓展」的标准。

### 画布（Konva）注意

Canvas **不认 CSS 变量**。M3 画布内颜色（背景、选区框）需走 JS 侧：`getComputedStyle` 读取 token，或维护一份 JS token 镜像。M0 不实现，但此约束先立，避免 M3 时画布颜色写死。

## 落地约定（M0）

```
src/
├─ app/
│  ├─ styles/
│  │  ├─ tokens.css        # 语义 token：:root（light 默认）+ [data-theme='dark']
│  │  └─ global.css        # reset + base；body 的背景/文字色用 token
│  ├─ theme/
│  │  └─ useThemeSync.ts   # 订阅 store.theme → 写 data-theme / localStorage / color-scheme
│  ├─ store/
│  │  └─ useAppStore.ts    # theme 字段（4 号文档已定的占位在此兑现）
│  └─ App.tsx              # 挂 useThemeSync
├─ routes/
│  └─ HomePage.tsx         # 主题切换按钮（冒烟入口）
index.html                 # 内联脚本：首帧前设 data-theme，防闪烁
```

### 校验

- `npm run typecheck` ✓、`npm run build` ✓
- 冒烟：点切换按钮 → `html[data-theme]` 变化、全站色变；刷新后保持所选；直连 URL 首屏无明暗闪烁；`prefers-color-scheme` 变化时未手动选过主题的会跟随。

### 关键约定

1. **组件样式只准写 `var(--color-*)` 等语义 token，禁止硬编码色值**——这是「可拓展」的根，违者主题切换必漏。
2. **token 只在 `app/styles/tokens.css` 一处定义**（单一真源），不散落到组件 `<style>`。
3. **主题切换不触发组件重渲染**，靠 CSS 级联；Zustand 的 `theme` 只管选中态与持久化。
4. **新增主题 = tokens.css 加一段 + 类型联合加一项**，不允许出现别的改法。
5. **`color-scheme` 与 `data-theme` 同步设置**，原生控件不缺席。

## 实现（M0）

### 依赖

无新增——复用 4 号文档已装的 `zustand`。样式侧零依赖：原生 CSS 变量 + Vite 原生 CSS Modules。

### 文件

```
src/
├─ app/
│  ├─ styles/
│  │  ├─ tokens.css            # 语义 token 唯一真源：:root（light）+ [data-theme='dark']
│  │  └─ global.css            # @import tokens；reset + body 基础样式（全部走 token）
│  ├─ theme/
│  │  ├─ theme-storage.ts      # app-theme 裸 key 读写、getInitialTheme、applyTheme
│  │  └─ useThemeSync.ts       # 订阅 store.theme → 写 data-theme / color-scheme / localStorage
│  ├─ store/useAppStore.ts     # theme 初始值改为 getInitialTheme()
│  └─ App.tsx                  # 装配层调用 useThemeSync()
├─ routes/
│  ├─ HomePage.tsx             # 主题卡片 + 切换按钮（冒烟入口）
│  └─ HomePage.module.css      # 只写 var(--token)，零硬编码色值
├─ main.tsx                    # import '@/app/styles/global.css'
index.html                     # 首帧前内联脚本设 data-theme（防闪烁）
```

### 切换链路

```
index.html 内联脚本（首帧前读 app-theme / 系统偏好）
        ↓ 设 html[data-theme] + color-scheme          ← 防闪烁
store.theme ← getInitialTheme()（localStorage > 系统偏好 > light）
        ↓ toggleTheme / setTheme
useThemeSync（App.tsx）→ applyTheme()
        ↓ 改 data-theme / color-scheme / localStorage
CSS 级联：所有 var(--token) 换值 → 全站重绘，组件不重渲染
```

### 校验

- `npm run typecheck` ✓
- `npm run build`：**当前 shell 的 Node 为 v14.17.5，Vite 7 要求 `^20.19 || >=22.12`，无法在此执行**（`??=` 语法错误）。需在 Node 20.19+ 环境补跑一次确认。
- 运行时冒烟（浏览器）：点「切换为黑夜 / 白天」→ 页面底色、卡片、按钮整体翻转；刷新后保持所选；首屏无明暗闪烁；未手动选过时跟随系统 `prefers-color-scheme`。

### 关键约定（实现侧补充）

1. **页面样式暂用 CSS Modules**（Vite 原生、零依赖、类名局部作用域）；token 仍是唯一色值来源，`HomePage.module.css` 内**零硬编码色值**。组件量上来（M2+）再统一评估样式方案（含是否引入 Tailwind）。
2. **存储用独立裸 key `app-theme`，不用 Zustand persist**——让 `index.html` 的内联脚本在首帧前能直接读，不依赖 store 内部格式。
3. **拆出 `theme-storage.ts` 避免循环依赖**：store 运行时依赖它取初始值，它对 store 只做 `import type`（编译期擦除）。
4. **画布（Konva）不认 CSS 变量**：M3 时画布颜色需 `getComputedStyle` 读取 token 或维护 JS 镜像，M0 未实现（约束已立）。
